# 可行性方案：Entity Embedding + Time-LLM + 河流水温

> 基于 [`00-PLAN.md`](00-PLAN.md) 四路联网调研（2026-07-25）的最终方案。
> **一句话：可行，niche 确实开着，但成败取决于能否打平 Padrón et al. (HESS 2025) 的 TFT。**

---

## 1. 定位：一句话卖点

> **在河流水温预测上，系统比较"把站点身份告诉 LLM"的全部方式——文本提示、文本嵌入、软提示、
> 数值嵌入、以及让 LLM 可微调——并给出何种载体在何种条件下有效的机制解释。**

**为什么这个卖点站得住**（三条调研共同支持）：

1. **水文侧空白**：Time-LLM/GPT4TS/任何重编程 LLM 用于河流或湖泊水温 = **零命中**；水文基础模型只做
   径流/水位；HESS 2025 综述明言"注意力 Transformer 尚未用于河流水温"。
2. **身份侧空白**：水温 DL 线**全部**用手工静态属性/图拓扑/逐站标定，**无人学习自由的每站嵌入**。
3. **方法侧空白**：实体嵌入+LLM 已在空气质量(LLMAir)/交通(ST-LLM/TPLLM)跑通，**从未跨进水域**，
   且**从未把实体嵌入本身当作研究对象**、**从未与水文默认的静态属性身份做对照**。

**必须诚实承认的**：单项"LLM 用于水温"是应用；单项"实体嵌入"已被占。**卖点必须是三者的交叉 +
机制解释**，不能是任何单项。

## 2. 必须击败的基准（不是稻草人）

| 基准 | 数据 | 身份机制 | 数字 |
|---|---|---|---|
| **Padrón et al. HESS 2025** ⭐ | **54 瑞士站** 2012–2022 | 静态流域属性 | **CRPS 0.70 °C**（1天 0.38 · 32天 0.90 · 新站 0.83 · 无监测 1.29） |
| Rahmani et al. 2021 | CONUS | 21 个专家静态属性 + 共享 LSTM | RMSE 0.81 °C / NSE 0.98 |
| air2stream | 逐河 | **每站一个标定模型** | 3–8 参数，仍是严肃基线 |
| **我们自己的 ICPR 2026** | 28 瑞士站 | 学习站点嵌入（开/关） | 需在本文中作为前作引用 |

> ⚠ **审稿人的必问题**：*"为什么 LLM 骨干该赢过在 54 站上调好的、带静态属性的 TFT？"*
> **答案只能来自消融，不能来自 framing。** 若最终 LLM 打不平 TFT，论文的正确形态是
> **"身份载体的受控比较 + 诚实的负结果"**，投 HESS/EDS，而不是硬吹 SOTA。

## 3. 实验矩阵（三因子）

### 3.1 主矩阵

| 因子 | 取值 | 现状 |
|---|---|---|
| **身份载体** | none · **文本提示**(a1/a3/a4) · **文本嵌入**(g) · **软提示**(b) · **数值嵌入**(c) · 冻结随机(容量对照) · 簇 ID(f) | c/文本 a1/随机 ✅已有；**b/g/a3/a4/f 待做** |
| **LLM 可训性** | **frozen** · **LayerNorm-only**(GPT4TS 方案) · **LoRA r=4** | 仅 frozen ✅；**本轮新轴** |
| **骨干** | Time-LLM(GPT2) ✅ · **TEMPO** · **CALF** · AutoTimes · GPT4TS(阴性对照) | 仅第一个 ✅ |

### 3.2 分阶段执行（按每 GPU-小时信息量）

| 阶段 | 内容 | GPU-h | 产出 |
|---|---|---|---|
| **P0 零算力** | **文本打乱诊断**：A 站描述配 B 站数据。指标不变 ⟹ **在自己设置里独立复现 text collapse** | **0** | 一张几乎零成本的强力图表 |
| **P1** | **软提示(b)** 每站 prefix，~40 行 | ~10 | 填补 text 与 additive 间**唯一空白中间点**；检验"瓶颈是 token 化还是注入位置" |
| **P2** | **LoRA 臂 × {none, text, numeric}**（2×3） | ~20–30 | **论文核心新颖性** |
| **P3** | **文本嵌入(g)**：句编码器冻结编码 28 条描述→投影→注入 | ~5 | 直接回答"**文本无用是语义无用，还是 token 接口无用**" |
| **P4** | **富描述(a3) + 统计量提示(a4)** | ~10 | 排除"**我们 prompt 太贫瘠**"这一竞争解释——**审稿人一定会问** |
| **P5** | 第二骨干 **TEMPO**（三轴全覆盖，零架构改动） | ~30 | 证明结论非 Time-LLM 独有 |
| **P6** | 规模轴：**Sadler 101 站**（1 天接入）→ 视结果再上 NWIS | ~30 | 28→101 站，检验嵌入在更多实体下的行为 |

**合计约 105–115 GPU-h**，UBELIX gratis 双并发下**约 2–3 周**可完成 P0–P5。

## 4. 预注册假设（双向，防止只写有利分支）

| # | 假设 | 若成立 | **若被推翻**（同等重要） |
|---|---|---|---|
| **H1** | 冻结时 数值 ≫ 文本 | 已测：−17.6% vs −1.9% | — |
| **H2** | **LoRA 后文本身份增益显著上升** | 结论升级为"**文本有效性取决于该通道是否可训练**"——机制主张 | ⚠ **很可能被推翻**：[2504.08808](https://arxiv.org/abs/2504.08808) 已在带 LoRA 的 CALF 上观察到文本仍不显著。**若我们也得 null ⟹ 对 text collapse 的独立确认 + 证明 LoRA 不是解药**，同样可发表 |
| **H3** | 软提示(b) 表现介于 文本 与 数值嵌入 之间 | 说明**瓶颈是 token 化**，连续注入即可解 | 若软提示≈数值嵌入 ⟹ 瓶颈**不在 token 化而在文本语义本身** |
| **H4** | 文本嵌入(g) > 文本提示(a1) | 说明**接口**是瓶颈，语义有用 | 若二者相当 ⟹ 语义确实无用（更强的 text collapse 证据） |
| **H5** | 富描述(a3) 不改变结论 | 排除 prompt 质量竞争解释 | 若富描述让文本追平 ⟹ **反转为正面结果**："文本可用，但须语义接地" |

## 7. 主要风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| **打不平 Padrón 的 TFT** | 中高 | 论文形态改为"载体的受控比较 + 诚实负结果"；**投 HESS/EDS/TMLR 而非硬吹 SOTA** |
| **H2 得 null（LoRA 也救不了文本）** | **高**（已有反证） | **已预注册为同等价值结果**——独立确认 text collapse + 证明 LoRA 非解药 |
| 28 站对 TS-LLM **喂不饱**（多假设 10k+ 步） | 高 | **把这一点作为发现写进论文**，而非实验失败；并用 P6 的 101/1000 站验证 |
| 全参微调过拟合 | **确定** | **实验设定里就写明只走 LoRA / 只调输出头**——诚实且可辩护的方法学选择 |
| "这只是应用" | 中 | 卖点必须是**交叉 + 机制**，且必须有 P0/P3/P4 的机制证据，不能只报精度 |
