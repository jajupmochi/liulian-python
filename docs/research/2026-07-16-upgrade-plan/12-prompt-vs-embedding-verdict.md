## 1. 问题 (a)：「加不加身份」的消融——**已被占据，不算贡献**

| 论文 | 身份机制 | 是否消融 |
|---|---|---|
| **ST-LLM**（[2401.10134](https://arxiv.org/abs/2401.10134)） | 数值节点嵌入 `E_s = σ(W_s·X_p+b_s)` | ✅ **已有 `w/o S`**（去掉空间/节点身份）；原文称去掉 T 或 S "similarly affects prediction error" |
| Time-LLM（[2310.01728](https://arxiv.org/abs/2310.01728)） | Prompt-as-Prefix（数据集背景/任务指令/统计量） | ✅ Table 6：去掉统计量 −10.2% MSE、去掉任务指令 >8%（few-shot >19%）——但是**数据集级，不是逐实体** |
| UniTime（[2310.09751](https://arxiv.org/abs/2310.09751)） | 域指令（**文本形式的域身份**） | ✅ 无指令则"域表示混在一起"——**域级，非实体级** |
| AutoTimes（[2402.02370](https://arxiv.org/abs/2402.02370)） | LLM 编码的**文本时间戳** | 时间身份，非实体身份（概念上最近的"文本作身份载体"） |
| 非 LLM 线：CN([2506.00432](https://arxiv.org/abs/2506.00432))、IndexNet([2509.23813](https://arxiv.org/abs/2509.23813))、EMAformer([2511.08396](https://arxiv.org/abs/2511.08396)) | 可学习通道身份嵌入 | ✅ 成熟且反复消融 |

**结论**：单独的 (a) 是**卫生对照，不是贡献**。审稿人会说"这是已知正面结果换个 backbone 重跑"。

## 2. 问题 (b)：「提示词 vs 嵌入」受控对比——**TS-LLM 内空白，但概念上被邻域占满**

**在 TS-LLM/ST-LLM 里确实找不到任何一篇**把同一份实体信息用两种方式注入并对比的论文。综述把两者
当作分类法的两支，而非同一信号的竞争编码。UrbanGPT(文本) vs ST-LLM(数值) 是**跨论文混淆**，无人桥接。

**但同样的结论在隔壁领域早已发表，审稿人一定知道**：

| 领域 | 代表 | 已发表的同向结论 |
|---|---|---|
| **LLM 推荐** | LLaRA([2312.02445](https://arxiv.org/abs/2312.02445))、IDGenRec([2403.19021](https://arxiv.org/abs/2403.19021))、Catalog-Native LLM([2510.05125](https://arxiv.org/abs/2510.05125)) | **"Title-LLM，仅靠自由文本标题，性能崩溃"**，ID+文本才最好——**就是我们的"数值≫文本"，只是换了任务** |
| 表格 LLM | LIFT([2206.06565](https://arxiv.org/abs/2206.06565))、TabLLM([2210.10723](https://arxiv.org/abs/2210.10723)) vs 嵌入管线([2502.11596](https://arxiv.org/abs/2502.11596)) | 文本序列化 vs 嵌入是长期对比 |
| **通用 LLM** | **Soft Injection of Task Embeddings Outperforms Prompt-Based ICL**（[2507.20906](https://arxiv.org/abs/2507.20906)） | **连续注入胜过自然语言注入（信息量固定）——我们头条的通用版** |

## 3. 问题 (c)：反噬风险——**"文本没用"是确认，不是发现**

**好消息**：Tan et al.（[2406.16964](https://arxiv.org/abs/2406.16964), NeurIPS 2024）**没有**直接抢先
——它消融的是 `w/o LLM`/`LLM2Attn`/`LLM2Trsf`，**从未单独消融文本通道**，也未比较注入模态。

**坏消息有三条**：

1. ⚠ 它的 **`woPre+woFT`（冻结随机初始化 backbone）就是我们的"容量对照"**——**我们的 frozen-random
   控制不是贡献，是标准做法**。
2. ⚠ **["Does Text Actually Help? Uncovering and Resolving Text Collapse"（2606.19413）](https://arxiv.org/abs/2606.19413)**
   已发表"**文本坍缩**"：文本分支"收敛到与内容无关的变换，无论输入描述如何都贡献可忽略的判别信号"。
   **这正是"文本通道几乎不携带信息"。**（表级细节 UNVERIFIED，代理只读了摘要/HTML 摘要）
3. ⚠ **[When Does Multimodality Lead to Better TSF?（2506.21611）](https://arxiv.org/abs/2506.21611)**
   16 数据集 7 域，结论是文本增益**条件依赖**于容量/对齐/数据量/互补性/显式性——
   **我们的"域依赖"是它的特例。**

## 5. 补强路线（按每 GPU-h 的说服力排序）

| 序 | 实验 | 作用 |
|---|---|---|
| **1（必做，最便宜）** | **提示词质量阶梯**：不透明索引 → 语义站名 → 丰富描述 → **oracle 描述（含嵌入本可学到的同样统计量）** | 若顶档数值仍胜 → **攻击 5 死**；若文本追平 → 得到**更好的正面结果**（"文本可用，但须语义接地"） |
| **2** | **解冻 LLM / 加 LoRA 做一档对照** | 把"LLM 忽略文本"变成"**冻结重编程接口才是瓶颈**"——机制主张，**直接答攻击 1** |
| 3 | 换更大 backbone（GPT-2 → Qwen-1.5B / Llama-3-8B） | 中和攻击 3；**若差距随规模单调收窄，本身就是头条** |
| 4 | 换第二个 reprogrammer（CALF/AutoTimes） | 杀攻击 4，但每小时信息量最低 |
| 5 | 机制探针：各注入模式下线性探针能否从隐状态恢复通道 id | 便宜，把基准结果变成证据 |

## 6. 最终建议：卖点必须重新表述

**不要**把头条建在 **"数值 ≫ 文本"** 上——那是可预测的测量结果，且隔壁领域已发表同向结论。

**要**把头条建在**你能定位的边界**上：

> **"文本身份在什么条件下不再落败，瓶颈在哪个接口。"**

即：reprogramming 式 TS-LLM 的提示词 token **没有通往逐通道路由的功能通路**，我们用探针/注意力
证明该通路缺失（而非仅仅报告精度更低），并用**提示词质量阶梯**与**冻结/可训对照**划出边界。
这样贡献从"文本输了"升级为"**这是文本停止输的条件，以及导致它输的接口**"——才够 anchor 级。

**在补强完成前**，此项在论文中的定位应为：**C5 的一个受控观察 + 次要贡献**，而不是主线卖点。
